POST FORMAT - HOW TO BUILD EACH BUFFER UPDATE FROM A MARKDOWN FILE

Every markdown file has a metadata header followed by the actual post body. Hermes must strip the header and post only the body.

The separator is the first standalone line containing exactly three hyphens. Everything before it equals metadata (do not post). Everything after it equals post body.

Example from week_01_mon_announce.md:

Week 1 - Monday Field Observation - LinkedIn
Pairs conceptually with blog post: Your ERP Went Live. Why Didn't Your Institution? (no link in body)
Format: approximately 150 words. First-person field observation from a public regional university. Standalone editorial - no blog tease, no URL, no question CTA.

(separator line of three hyphens)

A public regional university I worked with last quarter finished ERP cutover on schedule...
(rest of the post body - this is what Hermes posts to Buffer)

EXTRACTION RULE FOR HERMES
Step 1: Read file as UTF-8.
Step 2: Split on the first line that is exactly three hyphens, nothing else.
Step 3: Take everything after that line.
Step 4: Trim leading and trailing whitespace.
Step 5: That is the Buffer post text.

WEEKLY EMAIL VIA GOHIGHLEVEL
====================================================================

OPERATIONAL DETAIL LIVES IN A DEDICATED DOC
HERMES_EMAIL_CHAIN_INSTRUCTIONS.txt (same folder). That doc covers one-time setup of all 52 campaigns as GHL drafts and the trigger-based runtime loop that fires each email only after its paired blog returns 200 OK on 4ucit.com. The section below is the orientation summary.

MODEL
Trigger-based, not time-based. Each email is pre-loaded as a GHL draft during setup. The weekly loop polls the paired blog URL and schedules the campaign for send only after the blog is confirmed live. If a blog is late, the email waits (no dead links).

TARGET CADENCE
52 emails, one per blog, Tuesday at 09:00 America/New_York after the Monday blog publish. First target send: 2026-11-10. Last target send: 2027-11-02.

SEQUENCING WITH LINKEDIN DROPS
Monday 00:00 ET: blog goes live at 4ucit.com/insights/{slug} via GitHub Actions cron on Ultimate Consulting repo.
Monday 08:00 ET: LinkedIn Monday Field Observation (standalone editorial, no link, no blog tease).
Tuesday 09:00 ET: GHL email ships the recap and link to the new blog. This is the only channel that distributes the blog URL.
Wednesday 08:00 ET: LinkedIn Number Post.
Friday 08:00 ET: LinkedIn Question Post.

SOURCE OF TRUTH
hermes_email_manifest.csv. One row per email. Hermes reads it and pushes each row to GHL per the send date.

EMAIL MANIFEST COLUMNS
email_id: week_NN_email
week: 1 through 52
send_date: Absolute ISO date, Tuesday
send_time_local: 09:00
send_timezone: America/New_York
blog_slug: Published blog slug
blog_url: https://4ucit.com/insights/{slug}
blog_title: Verbatim blog title
blog_excerpt: Verbatim blog excerpt (one line)
email_subject: Subject line (same as blog_title by default)
email_preview_text: Preview text (defaults to blog_excerpt; GHL calls this preheader)
email_body_file: Relative path to the plain-text body file

BODY-FILE FORMAT
Each body file is UTF-8 plain text. Lines in order: salutation, opening hook (one paragraph lifted from the blog's lede), a two-line call-to-read with the blog URL, em-dash, Darryl Nash signature.

Token to substitute at send time: {{first_name|there}} (GHL merge-field syntax for first name with fallback "there").

Example from week_01_email.txt:

Hi {{first_name|there}},

The system goes live on schedule. The cutover is clean. The status report turns green. Three weeks in, your aid specialist is still running the old spreadsheet because the new workflow configures around a process that only lived in her head.

Read the full piece:
https://4ucit.com/insights/why-your-erp-goes-live-but-your-institution-doesnt

- end dash -
Darryl Nash
